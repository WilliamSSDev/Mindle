# Mindle

**A little learning. A lasting difference.**

Mindle is a flashcard study application with a FastAPI backend and a lightweight,
framework-free HTML/CSS/JavaScript frontend. Organize ideas into decks, create
cards, review them with spaced repetition, and listen to their text using local
browser speech voices.

The current design uses a charcoal canvas, violet accents and a responsive
sidebar. Its first release covers the dashboard, deck library, deck details,
card editor and review flow. The GitHub repository retains its original name,
`my-crud`; the product name is **Mindle**.

## Try the design without an account or database

From the project directory:

```powershell
python -m http.server 5500 --directory frontend
```

Open [the dashboard preview](http://localhost:5500/mindle/index.html?preview=1#dashboard).
You can also inspect the [deck library](http://localhost:5500/mindle/index.html?preview=1#decks)
and [card editor](http://localhost:5500/mindle/index.html?preview=1#create/1).

Preview mode is labeled **Design preview**. It uses sample content, makes no
backend API requests and keeps changes only in memory. Reloading resets it.
No frontend dependency installation or build step is needed.

## Current features

- Dashboard with today's reviews, due cards, streak and review activity.
- Deck library with search, due filters and grid/list views.
- Deck creation, card listing, rich-text card creation and confirmed deletion.
- Card preview, answer reveal, keyboard controls and four review ratings.
- Text-to-speech using voices the browser reports as local. No audio files are
  uploaded, generated by the application or stored in the database.
- Cookie authentication, registration, login, session refresh and logout.
- Responsive navigation and a light/dark appearance preference.

The existing statistics page is still available through **Statistics / Classic**.
Video learning, transcript selection and profile editing are not implemented in
this initial redesign. Live statistics use the metrics actually provided by the
backend; mastery and long-term retention are not inferred from sample data.

## Run the full application

### Requirements

- Python 3.10 or newer.
- pip and Git.
- Node.js 24 or newer for JavaScript tests and the optional browser smoke check.
- Chrome, Chromium or Edge for that optional browser check.

SQLite is sufficient for local development. The backend uses SQLAlchemy and
reads its connection string from `DATABASE_URL`; another database also requires
its corresponding Python driver, which is not included in the SQLite setup.

### 1. Clone the repository

```powershell
git clone https://github.com/WilliamSSDev/my-crud.git mindle
cd mindle
```

If you already have the project locally, use that directory instead.

### 2. Create a virtual environment and install dependencies

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

On macOS/Linux, activate it with `source venv/bin/activate`.
The virtual environment is local and is not part of the source repository.

### 3. Configure your environment

For a new checkout, copy the template:

```powershell
Copy-Item .env.example .env
```

Keep an existing `.env` if the application is already configured. The required
variables are:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | SQLAlchemy connection string; the example uses a local SQLite file. |
| `SECRET_KEY` | Your own randomly generated key for signing authentication tokens. |
| `ALGORITHM` | JWT signing algorithm, normally `HS256`. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Access-token lifetime, for example `30`. |

Generate a key with `python -c "import secrets; print(secrets.token_hex(32))"`
and put it in your local `.env`. The committed `.env.example` contains placeholders;
`.env` and local database files are ignored by Git.

### 4. Initialize a fresh development database

For a **new, empty** development database, create the current model tables:

```powershell
python -c "from app.models import Base, db; Base.metadata.create_all(bind=db)"
```

The repository includes historical Alembic revisions, but their legacy table
names and missing card-table creation do not form a complete fresh-install path
for the current models. Therefore `alembic upgrade head` is not the bootstrap
command for this version. Existing databases require a reviewed migration path;
`create_all` does not update columns in existing tables.

Do not run `app/models.py` directly to initialize data: its executable block drops
existing tables before recreating them. The command above only creates missing
tables and does not invoke that block.

### 5. Start FastAPI

From the repository root:

```powershell
python -m uvicorn app.main:app --reload
```

- [Application](http://127.0.0.1:8000/) - opens the Mindle workspace.
- [Login](http://127.0.0.1:8000/login_page.html) and
  [registration](http://127.0.0.1:8000/register_page.html).
- [Interactive API documentation](http://127.0.0.1:8000/docs).
- [Design preview](http://127.0.0.1:8000/mindle/index.html?preview=1#dashboard).

FastAPI serves the frontend, so a separate frontend server is unnecessary for
normal use. Press `Ctrl+C` to stop the server. Authentication cookies are currently
configured for local HTTP development.

## Text-to-speech

In the editor, select an installed voice and use **Listen to front** or
**Listen to back**. During review, **Listen** reads the question. Speech is handled
by the device's speech service through the Web Speech API; voices reported as
remote are excluded. Voice availability and languages depend on the browser and
operating system. If no local voice is available, the controls explain why speech
cannot be played. No audio-storage column or audio-file service is required.

## Project structure

```text
app/
  main.py                    FastAPI app, middleware and static frontend mount
  auth.py                    Password hashing and token helpers
  dependencies.py            Database sessions and authentication dependencies
  models.py                  SQLAlchemy database models
  schemas.py                 Request and response validation
  routes/                    Authentication, user, card and deck endpoints
  services/                  Shared deck lookups and review statistics
  DTOs/                      Current-user response mapping
alembic/                     Historical database migrations
frontend/
  index.html                 Entry page forwarding to Mindle
  mindle/
    index.html               Shared navigation and dialogs
    js/                      Views, routing, API service and preview data
    styles/                  Design tokens and application styles
  assets/                    Shared speech and retained legacy assets
  legacy-dashboard.html      Previous dashboard for comparison
  pages/statistics.html      Retained statistics page
  login_page.html            Existing login screen
  register_page.html         Existing registration screen
tests/                       Python and JavaScript regression tests
scripts/check-mindle-browser.mjs   Headless browser verification
docs/                        Architecture and change records
.env.example                 Environment template without credentials
requirements.txt             Python dependencies
```

The new frontend separates page templates, state/routing, API access, formatting
and icons. Its hash routes are `#dashboard`, `#decks`, `#deck/ID`, `#create/ID`
and `#review/ID`. See [the frontend guide](docs/FRONTEND.md) for the full module map,
backend contracts and implementation limits.

## Tests

With Python dependencies installed:

```powershell
python -m unittest discover -s tests -v
node --test tests/mindle.test.mjs tests/speech.test.mjs
```

The route tests use an isolated in-memory SQLite database. JavaScript tests check
preview isolation, API request contracts, formatting and local speech behavior.

For a real-browser smoke check:

```powershell
node scripts/check-mindle-browser.mjs
```

It starts its own temporary static server and headless browser, exercises the
preview flows on desktop/mobile, verifies no backend API calls are made and
prints a temporary screenshot directory. It does not use your normal browser
profile or write to your application database. Set `MINDLE_CHROME` to a browser
executable if automatic discovery cannot find one.
